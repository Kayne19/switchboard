# Task for code-reviewer

Perform a concise read-only final review of the current worktree diff. Focus only on the last repair: blank initial project transfers must load the model catalog and leave the picker usable when discovery succeeds; unavailable-catalog UI must be explicit; cross-control route/model/thinking serialization tests must be real. Also check that the earlier stale audio/transcript/session-token/recorder/playback fixes remain intact and static/app.js matches web/app.ts. Do not edit files or run a broad workflow. End with APPROVE or REQUEST_CHANGES and list only actionable findings.

## Acceptance Contract
Acceptance level: checked
Completion is not accepted from prose alone. End with a structured acceptance report.

Criteria:
- criterion-1: Return concrete findings with file paths and severity when applicable

Required evidence: changed-files, tests-added, commands-run, residual-risks, no-staged-files, review-findings

Finish with a fenced JSON block tagged `acceptance-report` in this shape:
Use empty arrays when no items apply; array fields contain strings unless object entries are shown.
`criteriaSatisfied[].status` must be exactly one of: satisfied, not-satisfied, not-applicable.
`commandsRun[].result` must be exactly one of: passed, failed, not-run.
`manualNotes` and `notes` are optional strings; an empty string means no note and does not satisfy `manual-notes` evidence.
